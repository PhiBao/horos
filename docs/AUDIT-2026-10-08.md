# Audit — 2026-10-08

An adversarial review of this repository, run with
[pashov/skills](https://github.com/pashov/skills) (solidity-auditor),
[cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill),
and [skraft9/vulnerability-research](https://github.com/skraft9/vulnerability-research).

Four hunters ran in parallel against the current commit — contracts and access
control, contracts and economics, the Worker and browser surface, and deployment
and keys — followed by a validation pass that compiled each candidate against the
code, and a regression test for every finding that was fixed.

The result was not a clean bill of health. Five findings were real, two of them
against sentences this repository makes about itself, and every fix below has a
test that fails if the guard is removed.

## What was found and fixed

| # | Finding | Severity | State |
|---|---|---|---|
| 1 | **Registration was first-to-type, not first-to-pay.** `register()` never verified payment, and the code comment claimed "there is nothing to squat on except by being the first to actually pay". A stranger could open the record at someone else's address and hold the payer half of it before the real business arrived — or take the name so the honest business could not register at all. | high | fixed |
| 2 | **A stale proposal could move the account twice.** `activate()` checked the proposal's own state and expiry, never that the account it moved *from* was still active. Two fully-signed proposals activated in submitter-chosen order, and the second overwrote the first — so the middle address never signed for the final move. | high | fixed |
| 3 | **A break disclosed mid-ceremony did not stop the ceremony.** A fully-attested proposal still activated after `discloseInheritance` marked the counterparty `Broken`, moving the account on a record that says the relationship is over. | medium | fixed |
| 4 | **Anyone could spend the vault.** `pay()` had no caller check. The destination is not a parameter, so a caller could not steal — but a stranger could push the whole balance to the recorded counterparty one cap-sized payment at a time, ref after ref. The per-payment cap never bounded the total. | medium | fixed |
| 5 | **A signature could be re-roled to stall a rotation.** The signed digest did not name the role it was made for, so a submitter could take the business's payer signature and spend it as a quorum signature: the payer half would never fill, and the move would stall until expiry — up to thirty days while invoice and registry disagreed. | medium | fixed |
| 6 | **The decision endpoint leaked internals and had no spend control.** A chain-read failure returned the raw RPC parser error to an anonymous caller, and the endpoint fans out to a paid judgment API with nothing throttling it. | low | fixed |
| 7 | **The keyless demo claimed it never read a key it read.** `demo-circle.ts` printed "this script never reads it" about `HOROS_DEPLOYER_PRIVATE_KEY`, then read it to sign the payer half — which is correct behaviour described by a false sentence. | low | fixed |
| 8 | **`CONFIRMED` was treated as settled.** Both settle helpers included `CONFIRMED` in their terminal set directly beneath a comment saying the terminal state is `COMPLETE`. A caller could read chain state and submit the next step against a transaction a reorg could take back. | low | fixed |
| 9 | **Deploy could delete the operator's own credentials.** `appendToEnvLocal` dropped every `HOROS_*` line, including the key the script had just used, while the docstring said the key could live in that file. | low | fixed |
| 10 | **Two environment loaders with different semantics.** `deploy.ts` carried its own copy of `loadEnv`, with the pre-fix precedence rule and a greedy value regex that kept trailing whitespace; the shared loader promised `#` comments it did not strip. | low | fixed |
| 11 | **`recover.ts` never read `.env`.** It read `process.env` directly, so an operator whose key lives in `.env.local` got a false "not set" refusal and the stranded funds stayed stranded. | low | fixed |

## What was checked and held

- **No XSS on any page.** Every attacker-controlled string — invoice text,
  counterparty name, injected instructions, reason details — is escaped before it
  reaches `innerHTML`, and no selector is built from user input.
- **No SSRF.** Every server-side fetch uses a constant URL; chain reads take an
  address that matches `0x[0-9a-f]{40}`.
- **No path traversal.** The asset fallback serves fixed paths; `/api/*` and `/c/*`
  are matched before it.
- **The custody wallet is never a valid signer for its own arrival**, in any role.
- **Bricking and quorum are already business-or-account only** — the earlier fix
  held against a fresh attack.
- **Secrets stay out of the repository and out of the browser.** `.env.local` and
  `.wrangler/` are ignored, no key reaches `worker/public/`, and the judgment key
  is a Worker secret used only as a bearer header.

## Deliberately not fixed, with reasons

- **`registerPayer()` is permissionless and grants proposing and quorum-attesting.**
  Registration no longer grants the payer half, so the worst it confers is the
  ability to *ask* for a move — which needs two other keys to become one. Left
  open on purpose: a registry that only the incumbent may join cannot bootstrap.
- **`isPayable()` scans every proposal a counterparty has ever had.** Measured:
  12,186 gas at zero proposals, 37,137 at sixty (`contracts/test/Adversarial.t.sol`).
  Linear, and the attacker prepays it in full — the address that abandons proposals
  pays for the addresses that read. Recorded rather than redesigned.
- **`discloseInheritance` is unilateral by either party.** Either side can mark the
  record Broken permanently. That is the design: the alternative to a disclosed
  break is a quiet one. Flagged so the trade is visible rather than accidental.
- **The rate limiting binding is permissive.** Cloudflare documents it as
  eventually consistent and "not to be used as an accurate accounting system", and
  measurements here agree: bursts pass, sustained load trips it eventually. It is
  wired to damp a loop, and the code says so. A deployment on a custom domain
  should put a WAF rate limiting rule in front of the path, which needs a zone.
- **`referenceUsed` is guessable if references are.** The demos use
  `keccak256("circle-inv-1")`. A real caller must use an unguessable reference, or
  a griefer who learns it can burn it first. Documented in the contract.

## Mutation check

A regression test is only worth what it proves, so each guard was deleted and the
suite re-run. All eight fail when their guard is removed, and were restored after:

```
guard removed                       suite fails
attest: stale proposal              yes (2 tests)
attest: broken record               yes (2)
activate: stale proposal            yes (4)
activate: broken record             yes (included above)
role bound into the digest          yes (2)
one key counts once per proposal    yes (2)
registration consent                yes (2)
business may not be the account     yes (2)
an existing id cannot be reinitialised  yes (2)
```

One of these was found *by* this check rather than by the audit: the re-roling test
passed for the wrong reason, because the business was not a registered payer in the
fixture and the payer lookup rejected the signature before the role check ran. It
would have kept passing if the role binding were removed. The fixture now registers
the business as a payer, so the role check is the only thing that can reject it.

The rate limiter is the exception and is not in that list: see "deliberately not
fixed". Its behaviour could not be reduced to a passing test from outside the
platform.

## Addendum — mainnet readiness (2026-10-08)

Checked, not assumed, because "deploy it to mainnet" is a decision with real money
behind it:

| Fact | Value |
|---|---|
| Arc mainnet | live, chainId 5042, head ~24.9M, gas 20 Gwei |
| Gas to deploy both contracts | **0.049 USDC** (registry 2,450,061 gas) + **0.015 USDC** (vault 744,812 gas) |
| Setup calls (setVault, setExecutor, caps) | ~0.006 USDC |
| Full ceremony at default amounts | 0.4 + 2.4 USDC into the vault |
| **Total to be live and moving real money** | **under 5 USDC** |
| Writable mainnet RPC | present and answering (QuickNode) |
| Deploy dry run | `eth_estimateGas` accepts both deploys against mainnet with the real bytecode |
| Circle key on mainnet | **refused.** `TEST_API_KEY` returns 400 for blockchain `ARC`; keyless mainnet signing needs a production Circle key |

The last row is the one that changes the shape of a mainnet run. Without a
production Circle key the mainnet ceremony runs on the local-signer path
(`pnpm demo`), which is the same contracts, the same policy and the same refusal —
but the agent holds a key, so the "the agent cannot talk its way past this" claim
weakens to "the agent is trusted, and the contract still refuses". Everything the
audit fixed lives in the contracts and applies either way.

Two risks worth stating plainly before any real money moves:

- **No external audit.** This repository's audit was run by agents and validated by
  regeneration; it is not a professional review. The contracts are immutable and
  hold real funds on mainnet.
- **Blast radius is a choice.** `globalCap`, `counterpartyCap` and the vault balance
  together bound what a bug can cost. On a first mainnet deployment they should be
  small enough that losing all of it is an acceptable price for the demonstration.
